### Using BMAD to streamline the build (after platform is chosen)

Once you've decided on a platform (Wix, Webflow, or Framer), use BMAD planning outputs as the **spec** that feeds the builder (AI or human). Same idea as the single-page test: reference + structured context → generate in the tool → swap in final copy and images.

**Recommended BMAD workflow order**

| Step | BMAD workflow | Output | How it streamlines the website build |
|------|----------------|--------|--------------------------------------|
| 1 | **Create Product Brief** (CB) | Product brief | Vision, audience, scope, success. Becomes the "what this site is for" context you paste (or summarize) into the builder or hand to a designer. |
| 2 | **Create PRD** (CP) | PRD | Requirements, user journeys, page-level needs. Use to define **page list** (Home, About, Services, Projects, Contact, etc.) and **per-page purpose** (what each page must do, key content, CTAs). Summarize each page into a short "page spec" or prompt for the builder. |
| 3 | **Create UX** (CU) | UX design | Core experience, components, design system, user journeys. Defines **sections and structure** per page type. Use UX deliverables to write builder prompts (e.g. "Hero + value prop + 4-step process + why us + CTA") or to guide a human. |
| 4 | **Create Wireframe** (CEW) | Excalidraw wireframes | Optional. Per-page wireframes become the **visual spec** (layout, blocks) for the builder or for Figma. Use when you want layout locked before generating in the tool. |

**How to use the outputs in the builder**

- **Per page:** Combine (1) page purpose + key content from the **PRD**, (2) section structure from **UX** (or from your model site), (3) **reference URL** (e.g. adventurewagon.com) or **wireframe**. That becomes the prompt/spec for that page in the chosen platform.
- **Paste or summarize:** If the builder's AI accepts long context, paste the relevant PRD/UX section for that page. If not, write a short "page spec" (like the homepage prompt in the appendix) derived from the PRD + UX.
- **Consistency:** Product brief + PRD + UX keep tone, structure, and goals consistent across all pages so you're not reinventing the brief for each one.

**Optional BMAD helpers**

- **Storytelling (ST)** — Use for hero copy, about narrative, or key messaging if you want BMAD to draft prose.
- **Editorial Review (EP)** — Use after drafting copy (in or out of the builder) to polish clarity and tone.
- **Research (MR/DR)** — Run before the brief if you want competitive or domain research to inform positioning and content.

**End-to-end flow**

1. **CB** → Product brief (vision, audience, scope).  
2. **CP** → PRD (pages, journeys, requirements).  
3. **CU** → UX (structure, components, design direction).  
4. **(Optional) CEW** → Wireframes per key page.  
5. For **each page** in the chosen builder: prompt = PRD page purpose + UX structure (+ reference URL or wireframe) → generate → add East Spruce copy and images → owner edit pass.  
6. Launch and hand off.

### Builder prompt (paste into Wix / Webflow / Framer AI)

Use this in the builder’s AI or prompt field; add the URL if the tool supports “build from URL.”

```
Build a homepage for East Spruce Design Build with this structure and style (reference: https://adventurewagon.com):

1. HERO — Full-width hero with a short headline (two-line punch, line one says "DESIGN FOR", Line two uses typewriter animation to cycle through phrases such as "Family", "Memories", etc.) , one subline, and one primary CTA button. Clean, confident, minimal text.

2. SOCIAL PROOF — One line under the hero, e.g. “Join X others…” or similar trust line.

3. VALUE PROPOSITION — Section with a bold headline (e.g. “THE ORIGINAL …” style), 2–3 sentences of supporting copy, then a clear CTA link.

4. PROCESS STEPS — Four horizontal steps with a number/label and a short CTA link each (e.g. Step One: Find Your Van → Step Two: Design Your Kit → Step Three: Select Install → Step Four: Hit the Road). Visual, easy to scan.

5. WHY CHOOSE US — Section headline, then 4–6 expandable or card-style blocks. Each block: short title + 2–4 sentences. Tone: professional, specific, benefit-focused.

6. GALLERY / STORIES — “Every [X] tells a story” style headline, subline, then image grid or carousel with a single CTA (e.g. “See what’s possible”).

7. PRODUCT/SERVICE PROMO — Headline (e.g. “THE GEAR SHOP”), then 3–4 category cards or links (e.g. Storage, Sleeping, Exterior, Off-Grid) with “Shop now” style CTAs.

8. FINAL CTA — One section: headline + one line of support copy + single CTA (e.g. “Get in touch”).

9. FOOTER — Multi-column nav (4–5 columns), newsletter signup (“Join the journey” + email), social links, copyright. Clean, organized.

Style: Modern, spacious, confident. Strong typography, clear hierarchy, plenty of whitespace. No clutter. Mobile-friendly. Replace all Adventure Wagon content with placeholder text and images so we can add our own. Reuse Adventure wagons color schemes. (company: East Spruce Design Build - architecture design firm).
```
